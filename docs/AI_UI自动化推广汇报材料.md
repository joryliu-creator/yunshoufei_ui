# 云收费 UI 自动化与 AI 辅助回归测试推广建议

## 一、项目背景

云收费是天启平台的下游产品，依赖基础、客户管理、能耗和收费配置等上游数据。传统回归测试需要反复准备房间、客户、收费项、收费标准、仪表及用量数据，随后人工进入多个出账入口核对金额并清理账单，执行时间长且容易受重复数据影响。

本项目采用 AI 辅助分析业务、Python Playwright 自动化执行、pytest 组织用例、Page Object 封装页面的方式，目标是把稳定、可重复的回归流程沉淀为代码和 Excel 用例资产。

## 二、解决方案

### 1. 分层架构

```text
Excel 回归用例/业务映射
          ↓
pytest 用例编排
          ↓
Page Object 页面对象
          ↓
Playwright 浏览器执行
          ↓
金额断言、状态断言、数据清理
```

### 2. 业务入口隔离

按实际业务拆分入口和清理流程，避免将不同模块混为一个场景：

- 账单中心：创建账单，按唯一账单编号作废、删除。
- 计费出账-常规类：周期类、仪表类账单，经过计算、核对、审核，再到账单中心清理。
- 计费出账-临时类：临时类、押金类账单，按临时出账流程创建，再按对应入口清理。
- 临时台账：独立的高级搜索、作废、删除流程。

### 3. 稳定性策略

- 房间树、收费项树、日期控件采用“等待可见后再输入或选择”。
- 默认串行执行，优先稳定性，不追求盲目并行和极限速度。
- 登录失败或提示“账号在其他地方登录”时，按正常登录流程恢复，不将提示弹窗误判为失败。
- 登录后关闭通知、公共公告等遮挡弹窗。
- 每条测试产生唯一数据并记录账单编号，失败时优先清理待处理数据。

## 三、当前成果

- 已建立 Python + Playwright + pytest + Page Object 自动化框架。
- 已建立环境、客户、账号和业务参数分离机制。
- 支持标准1、标准2环境复用；green/blue 由用户在门户侧切换，不在脚本中重复拆分。
- 已按入口和业务类型建立回归矩阵：
  - 周期类：44 条
  - 仪表类：24 条
  - 临时类：22 条
  - 押金类：12 条
  - 合计：102 条可执行场景，另有模板场景 5 条
- 已沉淀房间、客户、收费项、收费标准、仪表和线下用量等前置数据模板。
- 已实现账单金额、账期、账单状态和清理结果等关键断言。
- 已处理多层 iframe、Element UI 弹窗、房间树和收费项树等复杂控件。
- 已形成业务知识和自动化执行规则 skill，可继续复用于其他云收费场景及禅道缺陷回归。

## 四、预期收益

### 测试效率

- 重复性出账、审核、作废和删除操作由脚本执行，减少人工点击。
- 同一套用例可切换客户号、项目和环境执行，降低重复维护成本。

### 测试质量

- 预期金额由收费标准和映射表计算，避免只验证“页面提示成功”。
- 自动校验账单状态、账期、金额和清理结果，降低漏检概率。
- 通过唯一账单编号清理，减少误删其他测试数据的风险。

### 知识沉淀

- 操作步骤、测试数据、业务规则和脚本相互关联，新成员可以按模板扩展。
- 复杂业务规则（不足月、阶梯、系数、累计用量、违约金等）可逐步沉淀为可复用资产。

## 五、当前边界与风险

- 房间、客户迁入、收费项绑定、仪表和线下用量等前置数据，目前以人工或模板导入为主；后续可根据接口权限再自动化。
- 违约金减免依赖定时任务，需研发确认可调用接口或可控的任务触发方式。
- 押金缴费、退款、抵扣会影响押金台账，不能套用普通账单的自动删除策略，必须单独定义数据生命周期。
- 真实账号密码只允许维护在本地环境文件，不进入 Excel、代码、日志或 Git。
- 生产环境默认只读，不执行创建、作废和删除操作。

## 六、部门推广建议

### 第一阶段：标准化

统一目录结构、环境配置、账号管理、Excel 字段、日志格式和清理规则；选择一个业务稳定、数据准备充分的模块作为试点。

### 第二阶段：场景复制

各产品测试人员只需提供：

1. 页面业务流程和验收标准；
2. 环境、客户号、项目和账号角色；
3. 收费/计算规则及预期结果；
4. 可复用或可导入的前置数据模板。

AI 辅助整理业务步骤和断言，测试人员负责确认业务语义及关键数据。

### 第三阶段：持续回归

接入 CI 或定时任务，按环境和业务标签执行；输出通过率、失败原因、截图、日志和待清理数据报告。对于失败用例，先区分环境/数据问题、定位问题和产品缺陷，再决定是否提禅道缺陷。

## 七、推广验收指标建议

- 重点回归场景自动化覆盖率逐步达到 60% 以上。
- 核心流程单次执行成功率达到 95% 以上。
- 自动清理成功率达到 98% 以上；清理失败必须有明确告警。
- 新增一个同类业务场景的脚本改造时间控制在 0.5～1 个工作日内。
- 每次执行均可追溯到环境、客户、场景、账单编号和断言结果。

## 八、结论

该项目已经从“单次 AI 协助操作”演进为“业务知识 + 数据模板 + 自动化框架 + 回归用例”的组合资产。建议以云收费为试点，先推广标准化的场景建模、参数化、稳定定位和安全清理规范，再逐步复制到其他产品，形成部门级 AI 辅助自动化回归模式。
