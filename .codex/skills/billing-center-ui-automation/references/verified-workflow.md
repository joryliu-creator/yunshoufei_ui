# 已验证 Demo 与页面规则

> 本文件只记录 `D:\lz\autotest` 的已跑通实现、定位细节和基准测试数据。产品模型、收费领域语义、跨项目稳定 UI 规律与通用安全边界以 `$cloud-billing-product-knowledge` 为唯一公共来源；发现通用规则时先更新公共 Skill，本文件仅补充代码实现所需的项目特例。

## 人机协作边界

- 陌生业务首次探索由熟悉业务的测试人员主导。AI独立操作时不清楚隐含规则，而且逐步读取页面和工具调用有延迟，速度通常低于熟练人工。
- AI适合旁路记录操作、补充检查点，并把人工确认后的流程转成 Excel、Page Object、pytest 脚本和 Skill。
- 后续重复回归由 Playwright 执行，AI辅助分析截图、Trace和日志；业务缺陷定性、资金操作授权和发布结论仍由测试人员负责。
- 衡量价值时重点比较“人工确认场景转为自动化资产”的耗时和后续重复回归收益，不用首次 AI 独立探索速度证明价值。
- 页面定位遇到同一阻塞问题时，允许自行切换 DOM、截图、独立 Playwright 和只读回查等方式；只有同一问题连续 20 分钟仍无有效进展，才请求业务测试人员协助确认页面步骤。

## 计费出账与账单中心的并行边界

- 两个模块均可出账，且复用同一套上游数据与出账资格：客户、项目、房间、房间收费设置、收费项、收费标准、生效期及相应的仪表/用量数据。数据源一致不代表页面交互、状态流转或清理入口可以混用。
- 账单中心是直接创建账单的入口；计费出账是“计算 → 核对 → 审核 → 出账”的工作流入口。两者必须分别建 Page Object、测试步骤和状态断言，但可复用同一收费场景、金额计算器和预期金额。
- 用户已确认的计费出账范围：常规类出账用于周期类和仪表类账单；临时类出账用于临时类和押金类账单。未被确认的收费类型不得自行归入任一入口。
- 当前常规类费用计算抽屉对周期类和仪表类都使用“开始月份 / 结束月份”组件；仪表类回归 2026-08 时两端均选择 `2026-08`。不得在该月份组件中强填 `YYYY-MM-DD` 日期范围。
- 账单中心创建完成后按账单状态、金额和唯一账单编号断言，并按编号作废、删除；计费出账还必须依次断言计算完成、核对、审核通过和可在账单中心查看。计费出账审核通过后，必须在账单中心按“账期 + 房间 + 未作废”筛选出唯一账单，再作废、删除；不得在计费出账页面继续创建或按卡片删除已出账数据。

## 临时台账动态参数定位

- 临时台账业务内容必须定位到 `iframe[src*="busH5Url"][src*="temporaryBill"]`；不得依赖页面中 iframe 的先后顺序。
- 选择收费标准后，人工输入金额、仪表用量和数量公式均只出现一个可编辑的动态参数输入框。可限定在创建弹窗内，使用 `input.el-input__inner[placeholder]:visible:not([readonly]):not([disabled]):not([placeholder="选择年月"])`，并要求唯一；只在 Excel 场景明确给出相应参数时填写。
- 天数公式使用两个 `input.el-range-input:visible`。开始和结束日期均填写后分别按 Enter，再按 Escape 关闭日期层；已验证“今天至明天”可正确保留结束日期。
- 对人工金额、仪表用量或数量公式：填写动态参数后，必须点击页面其他位置使输入框失焦，并等待 `POST /temporaryBill/queryTempFeeStandardTotalFeeAmount` 返回成功；同时断言只读“收款金额”已显示场景预期值，最后才点击创建弹窗底部唯一的“确定”。不能把页面刚显示的金额当作已完成异步计算，更不能填写或要求填写“账单接收人”。2026-08-18 已用房间 1012（用量 20、金额 120.00）真实验证创建、作废、删除全流程。
- 先用不点击最终“确定”的预检脚本验证动态值和日期范围。只有预检通过、创建开关已授权时，才执行真实创建与按账单编号清理。

## 最终确认的创建顺序

1. 打开 `index.html#/Home?masterCustomerId=...`，复用已保存登录状态。
2. 由最上层向下关闭登录后异步出现的 Element UI 弹窗，并收起右侧“在线客服”。
3. 进入“云收费/账单中心”，在 `iframe[src*="BillingCenter"]` 中等待创建按钮可见且 loading mask 消失。
4. 选择项目“云收费自动化MS1”。项目已是目标值时不重复操作；只读输入框可能被 `span.textOverflow` 覆盖。
5. 点击“创建账单”。
6. 清空房间输入框后再次点击，等待房间树根节点真实出现；再输入目标末级房间号。双栏选择器使用左侧“房间名称”搜索框（右侧仅筛选已选房间，不得使用）；紧凑树选择器则使用已打开的原房间输入框。
7. 等待唯一筛选结果出现，勾选目标叶子节点并确认 checkbox 已选中；不得逐层展开整棵房间树。
8. 点击房间树弹窗的“确定”。这是必需步骤，只有确认后系统才查询房间收费项；随后断言目标房间 tag 已出现。
   - 房间树可能先渲染空容器；等待后仍没有根节点时，允许关闭、间隔后重开，最多有限次数。
   - 若 `getBuildRoomNew` 返回 HTTP 200 但树显示“暂无数据”，必须停在提交前并记录为环境/接口阻塞；接口恢复后只补跑尚未创建账单的场景，不得把它误报成金额断言失败。
9. 选择账期目标月份和应收日期。日期/月弹层关闭后再操作后续控件。
10. 点击账单明细右侧“新增收费项”，等待收费项抽屉及列表加载。
11. 在收费项抽屉输入目标收费项名称，勾选收费项，点击右下角“确定”返回创建抽屉。
12. 点击新增收费项右侧“编辑”，填写最晚缴款日为执行当天；计费期间和“用户端展示计费期间”保持原值。
13. 点击新增收费项操作栏“保存”，再点击创建账单抽屉右下角“确定”。
14. 在账单通知提示中点击“不需要”，从唯一结果行读取并记录系统生成的账单编号。

## 最终确认的清理顺序

1. 返回账单中心，按账期起止月份筛选目标账期并触发搜索。
2. 使用刚创建的账单编号精确定位目标，不能只依赖筛选后“恰好一条”。
3. 勾选该账单，并收起可能遮挡操作区的“在线客服”。
4. 点击“更多/批量作废”，不再使用单条作废。
5. 填写作废理由，例如“UI自动化Demo数据清理”。
6. 点击“确定作废”，断言状态变为“已作废”。仅完成作废并不代表清理结束。
7. 再次勾选同一账单，点击“更多/批量删除”。
8. 删除提示可能不是 ARIA dialog。从包含“删除后不可恢复/确定删除”语义的文本向上寻找带按钮的最近祖先，再点击“确定”。
9. 搜索并断言该账单编号不再出现在列表。

## 页面定位经验

- 页面含多个 iframe，先锁定账单中心 iframe。
- `.el-select-dropdown:visible` 在动画期间可能短暂出现两个，选项也可能从 0 个异步变为 1 个；应使用可重试断言等待目标选项唯一出现，不能在固定等待后沿用等待前的数量判断。
- Element UI 固定列会把同一业务行拆到左、中、右三张表。以账单编号所在的唯一业务行作为权威定位，再分别处理固定列。
- 登录态可能同时依赖 cookie 和 sessionStorage；恢复后必须断言主页菜单可见。
- 正确登录 URL 是 `index.html#/login`，不要写成 `index.html/#/login`。
- 登录后弹窗可能异步叠加，关闭按钮要限定当前可见 dialog/drawer，避免误关业务弹窗。
- 通知弹窗可能在首次遮挡层清理之后再次异步出现。如果它挡住“在线客服”收起按钮，应重新清理可见弹窗并重试，再使用安全的 DOM 收起兜底。
- 项目选择组件的只读 input 被显示文本覆盖时，不要对 input 使用强制点击；应点击其 `.jie-project` 外层组件，再根据 `aria-describedby` 限定关联的可见项目树弹窗。
- 当前账单中心创建流程通过“新增收费项抽屉 → 勾选收费项 → 编辑收费明细 → 保存”完成收费项配置；不要再按旧版同一明细行中的收费类型/收费项下拉框定位。

## 数据和安全开关

业务变量包括 `PROJECT_NAME`、`ROOM_PATH`、`CHARGE_TYPE`、`CHARGE_ITEM`、`BILLING_MONTH`、`RECEIVABLE_DATE`、`LATEST_PAYMENT_DATE` 和 `VOID_REASON`。

- `ALLOW_BILL_CREATION=true` 才允许创建。
- `CLEANUP_CREATED_BILL=true` 表示创建后请求清理。
- `ALLOW_BILL_DELETION=true` 才允许永久删除。
- 清理要求后两个开关同时为 true，默认都为 false。

账号密码、storage state 和 token 属于秘密或运行态数据，只在本地安全配置维护，不进入 Skill、代码、Excel 或测试报告。

Excel 的“收费场景配置”工作表按“一行一个计算场景”维护：环境、客户、专用房间、收费项、收费标准、生效时间、计费公式、计算参数和预期金额。收费标准或计算配置互相冲突时必须使用不同房间；多个不冲突用例可以引用同一场景编号。模板和待补充行不得执行，只有“维护状态=已核验”且“是否启用=是”的场景可供自动化读取。

Excel 数据职责必须保持单一：用例清单的“场景引用/覆盖项”只通过 `SCENARIO_ID` 引用场景，账号别名取该行“账号/角色”；“收费场景配置”是项目、房间、收费配置、减免与金额预期的唯一维护入口；“运行参数”只维护环境、客户、账期、日期、通知选择和清理原因。禁止把项目、房间、收费项或收费标准复制到“运行参数”。

执行代码必须真正读取 Excel，链路为“用例编号 → SCENARIO_ID → 收费场景配置 + 运行参数”。配置表标题同时展示 `${PROJECT_NAME}`、`${ROOM_PATH}` 等变量名，保证步骤参数可追溯。`ALLOW_BILL_CREATION`、`CLEANUP_CREATED_BILL` 和 `ALLOW_BILL_DELETION` 属于本地授权，只允许从 `.env` 读取，绝不能由 Excel 打开。

## 多账号与角色切换

- 配置层级固定为“环境 → 客户 → 账号/角色 → 可访问项目 → 业务数据”。当前已确认 `standard1` 使用 HTTP，入口为 `http://t.jslife.net`，客户号 `93537` 属于该环境；其他环境和客户必须由本地配置显式维护。
- Excel “账号角色”工作表维护环境、客户号、稳定账号别名、业务角色、可访问项目和权限说明，不维护真实用户名或密码。
- 本地 `.env.<环境>` 优先使用 `C<客户号>_<别名大写>_USERNAME`、`C<客户号>_<别名大写>_PASSWORD`、`C<客户号>_<别名大写>_CAPTCHA` 保存凭据，例如 `C93537_BILLING_ADMIN_USERNAME`。
- 使用 `python scripts/save_auth.py --environment <环境> --customer-id <客户号> --account <别名>` 保存到 `.auth/<环境>/<客户号>/<别名>/user.json` 和 `session-storage.json`。
- 单账号用例可用 `@pytest.mark.customer("客户号")`、`@pytest.mark.account("别名")`，整次运行可用 `--test-env`、`--customer-id`、`--account-role`。
- 同一端到端用例切换角色或客户时，使用 `account_context("别名", "客户号")` 创建独立上下文。不要在同一 browser context 中通过退出再登录切换账号。
- `standard1` 在新目录尚未生成时兼容旧 `.auth/<别名>/` 和 `.auth/user.json`，仅用于平滑迁移；新登录态必须按环境和客户隔离。
- `prod` 不得开启创建账单、自动清理或永久删除开关，带 `side_effect` 标记的用例会被强制跳过。

## 收费公式基准房间命名

- 房间导入数据以 `房间导入模版.xlsx` 第一条数据为字段模板，只允许批量替换“房间号”，位置、楼层、业态、面积、装修、状态等字段保持原值。
- 基础模块对房间名称有长度和字符限制，房间导入模板统一使用从 `1001` 开始的连续短编号，不再把公式写入房间名称。
- 单独维护 `房间收费标准映射表.xlsx`，记录“房间名称、收费类型、原始计费公式、计费面积类型、不足月计费规则、建议收费标准名称”，用它恢复短编号对应的业务含义。
- 计费公式保持系统原始名称。公式文本出现“计费面积”时，必须生成建筑面积、使用面积、收费面积三个场景；收费标准名称将“计费面积”替换成实际选择的面积类型。
- 周期类收费标准名称沿用替换面积后的公式名称；临时类、押金类、抽成类、水表仪表类、电表仪表类增加类型前缀，避免其他同名标准混淆。
- 每个周期类“公式 + 计费面积”都必须分别创建“按天”和“按满月”两个标准，使用不同房间，名称末尾分别追加 `-按天`、`-按满月`；非周期类不使用该维度。为兼容已创建数据，按天及非周期房间保留 `1001～1047`，按满月房间从 `1048` 起依次对应各按天周期场景。
- 生成后检查房间名称总数与唯一数一致，并验证除“房间号”外的所有字段仍与模板行相同。

## 收费标准新增——周期常用公式

- UI 自动化场景的适用项目是“云收费UI自动化”；“云收费自动化MS1”和“云收费自动化MS2”属于接口自动化项目，不得用于本批 UI 收费标准。
- 固定输入顺序：收费类型“周期类” → 收费项“UI周期性收费项” → 适用项目 → 收费标准名称 → 不足月计费规则 → 计费公式。
- 选择周期类收费项后出现必填项“不足月计费规则”，默认“按天计费”，另有“按满月计费”。
